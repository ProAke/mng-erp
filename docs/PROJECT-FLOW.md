# คู่มือ Project Brief, Mindmap, Flow และ Docs

คู่มือนี้ใช้กับ MNG ERP รุ่นที่มีเมนู **ผังงาน** และ **คู่มือ** โดยยังใช้ Vanilla JS SPA และ Express/MariaDB เดิม

> Mindmap และ Flow สร้างจากแม่แบบและคำตอบในบรีฟ **ไม่ใช่ผลจากโมเดล AI** การเลือก Agent/โมเดล หรือกำหนดขั้นตอนแบบอัตโนมัติเป็นการวางแผน ไม่ได้เรียกผู้ให้บริการ AI เชื่อม Webhook ส่งข้อความ เผยแพร่สื่อ หรือปิดการขายจริง

## เริ่มโปรเจกต์ใหม่

1. เปิด **โปรเจกต์ → เพิ่มโปรเจกต์** ตั้งชื่อ รหัส ลูกค้า งบประมาณ วันที่เริ่มและวันส่งมอบ
2. ตอบคำถามเรื่องเป้าหมาย ลูกค้า สิ่งส่งมอบ ตัวชี้วัด และข้อจำกัด สามารถเว้นคำตอบที่ยังไม่ทราบได้
3. ระบุช่องทางสื่อและ Lead วิธีขาย ผลิต ตรวจคุณภาพ ส่งมอบ และดูแลหลังการขาย
4. เลือกสมาชิกจากเมนู **ทีม** ผู้ประสานงาน ผู้อนุมัติ และ AI Agent ที่มีใน **AI Hub** พร้อมเลือกหรือระบุชื่อโมเดล หากยังไม่มี ผู้ดูแล/Manager เพิ่มสมาชิกหรือ Agent ได้จากขั้นตอน **ทีม & AI** ในบรีฟ รายการจะบันทึกเข้า **รายชื่อส่วนกลางทันที** แม้ภายหลังยกเลิกบรีฟ การเพิ่มสมาชิกไม่สร้างบัญชีเข้าสู่ระบบ และการเพิ่ม Agent ไม่เชื่อมผู้ให้บริการ AI
5. ตรวจสอบข้อมูล หากต้องการสร้างการ์ดงานจากผังทันที ให้เลือกช่อง **สร้างการ์ดงานจากขั้นตอนในผังด้วย**; ค่าเริ่มต้นไม่เลือก
6. กด **สร้างโปรเจกต์ & ผัง** ระบบบันทึกโปรเจกต์ บรีฟ Mindmap และ Flow พร้อมกัน หากเลือกสร้างงาน ระบบสร้างการ์ดงานในโปรเจกต์ด้วย

ข้อมูลเหล่านี้จะบันทึกใน MariaDB เมื่อแอปเชื่อมต่อฐานข้อมูลจริง ข้อมูลในโหมดสาธิตเก็บในเบราว์เซอร์เท่านั้นและไม่ใช่ข้อมูลของทีม

## อ่านและปรับ Mindmap / Flow

- เปิด **ผังงาน** แล้วเลือกโปรเจกต์ หรือคลิก **บรีฟ · Mindmap · Flow** บนการ์ดโปรเจกต์
- **Mindmap** สรุปเป้าหมาย กลุ่มลูกค้า สิ่งส่งมอบ สื่อ การขาย การผลิต ทีม และการดูแลลูกค้าจากบรีฟ
- **Flow** แบ่งเป็น 4 โซน: Marketing & Media → Lead & Sales → Production & Delivery → Customer Success เส้นประแสดงการแก้ไข QC และนำ Feedback มาต่อยอด
- ลากพื้นที่ว่างเพื่อเลื่อนผัง ใช้ปุ่ม `+`, `−`, **พอดี** หรือล้อเมาส์เพื่อซูม; ใช้ปุ่มลูกศรเมื่อโฟกัสที่พื้นที่ผังเพื่อเลื่อนด้วยคีย์บอร์ด
- คลิกการ์ดเพื่อดูรายละเอียด กำหนดคนรับผิดชอบ Agent/โมเดล เพิ่มรายการตรวจสอบ และประมาณชั่วโมง
- ผู้มีสิทธิ์แก้ไขสามารถเพิ่ม ลบ และเลื่อนลำดับขั้นตอนภายในโซนได้ เมื่อเปลี่ยนโซน ขั้นตอนจะย้ายไปท้ายโซนใหม่ เส้นทางจะเรียงใหม่ตามลำดับขั้นตอน
- กด **ตั้งค่าบรีฟ** เพื่อปรับคำตอบ Mindmap จะอัปเดตจากคำตอบล่าสุด ส่วนขั้นตอนที่แก้เองและลิงก์ไปยังงานจะยังอยู่
- หากเปิดโปรเจกต์ที่สร้างก่อนมีฟีเจอร์นี้ ระบบแสดงตัวอย่างที่ **ยังไม่บันทึก** กด **ตั้งค่าบรีฟ** เพื่อเริ่มบันทึก ไม่มีการแก้โปรเจกต์เก่าโดยอัตโนมัติ

### สิทธิ์และการแก้ไขพร้อมกัน

- ทุก endpoint อยู่หลังการเข้าสู่ระบบ อ่านผังและคู่มือของทีมได้โดยผู้ใช้ที่เข้าสู่ระบบ
- การแก้ผังและสร้างงานจากผังต้องเป็น `manager`, `admin` หรือ `super_admin` ตามสิทธิ์จัดการโปรเจกต์เดิม
- การบันทึกผังตรวจ `revision`: ถ้าผู้อื่นบันทึกก่อนจะได้ HTTP `409` เพื่อไม่เขียนทับ ให้คัดลอกสิ่งที่กำลังแก้ กดยกเลิกและ **รีเฟรช** แล้วลองใหม่
- ผู้ใช้ที่เข้าสู่ระบบสามารถสร้าง/แก้คู่มือทีมได้ การลบคู่มือต้องใช้ `manager`, `admin` หรือ `super_admin`
- ผังและคู่มือทีมมองเห็นได้ทั่วทั้ง workspace ไม่ใช่พื้นที่ลับ ห้ามใส่รหัสผ่าน Token API Key หรือข้อมูลลูกค้าเกินจำเป็น

## สร้างงานจากผัง

กด **สร้างงานจากผัง** เพื่อสร้างงานเฉพาะขั้นตอนที่ยังไม่มีงานเชื่อม หรือคลิกการ์ดและเลือก **บันทึกและสร้างงาน** เฉพาะขั้นตอนนั้น ระบบจะถามยืนยันก่อนสร้าง

- การกดซ้ำหรือส่งคำขอพร้อมกันไม่สร้างงานซ้ำสำหรับขั้นตอนที่เชื่อมงานแล้ว
- งานเริ่มสถานะ `todo` และใช้วันส่งมอบโปรเจกต์เป็นกำหนดส่งตั้งต้น โปรดปรับวันและความสำคัญจริงในบอร์ดงาน
- งานเก็บชื่อ รายละเอียด ผู้รับผิดชอบ Agent และรายการตรวจสอบ ณ เวลาสร้าง การแก้ Flow ภายหลัง **ไม่เปลี่ยนงานที่สร้างไปแล้ว**; กดดูงานที่เชื่อมเพื่อแก้การ์ดงานโดยตรง
- ลบขั้นตอนออกจากผัง **ไม่ลบงานที่เชื่อมไปแล้ว** และงานที่ถูกเก็บเข้าคลังจะไม่สร้างซ้ำโดยอัตโนมัติ
- การสร้างงานไม่เริ่ม AI ส่งข้อความ หรือเผยแพร่สื่อ ทีมต้องดำเนินการผ่านช่องทางที่เชื่อมต่อและได้รับอนุญาตจริง

## คู่มือ & Docs

เมนู **คู่มือ** มีคู่มือสำเร็จรูปสำหรับการเริ่มใช้งาน ผังโปรเจกต์ ทีมและ AI สื่อ การขาย การดูแลลูกค้า และ Hermes API สามารถค้นหาหัวข้อจากกล่องค้นหา

กด **เขียนคู่มือทีม** เพื่อสร้าง SOP หรือนโยบายภายใน เลือกหมวดหมู่และผูกโปรเจกต์ได้ รูปแบบข้อความรองรับหัวข้อ `#`, `##`, รายการ `-` และลำดับเลข HTML ที่ผู้ใช้ใส่จะแสดงเป็นข้อความ ไม่ถูกเรียกทำงาน ผู้ใช้ที่เข้าสู่ระบบเห็นคู่มือทีมร่วมกัน

## API ที่เกี่ยวข้อง

ทุกคำขอข้อมูลต้องใช้ session หรือ Hermes token ที่ได้จากการเข้าสู่ระบบ ดูตัวอย่างการล็อกอินใน [API-MANUAL.md](API-MANUAL.md)

| Method | Endpoint | การใช้งาน |
| --- | --- | --- |
| `POST` | `/api/projects` | สร้างโปรเจกต์และผังตั้งต้นเสมอ ส่ง `brief` หรือ `flowData` ได้ และเลือก `autoCreateTasks: true` หากต้องการสร้างงานทันที |
| `GET` | `/api/projects/:id/flow` | คืน `{exists, flow}`; โปรเจกต์เดิมที่ยังไม่มีผังคืน `exists: false` |
| `PUT` | `/api/projects/:id/flow` | บันทึกผังทั้งชุด ต้องส่ง `revision` ล่าสุด; ใช้ `0` สำหรับผังแรกของโปรเจกต์เดิม |
| `POST` | `/api/projects/:id/flow/sync-tasks` | สร้างงานที่ยังไม่เชื่อม ส่ง `nodeId` เพื่อสร้างเฉพาะขั้นตอน และส่ง `revision` เพื่อป้องกันใช้ผังเก่า |
| `GET`, `POST` | `/api/docs` | อ่านหรือสร้างคู่มือทีม |
| `PATCH`, `DELETE` | `/api/docs/:id` | แก้ไขหรือลบคู่มือทีม (`id` เช่น `doc1`; ลบจำกัดสิทธิ์) |

`PUT` รับข้อมูลผังเต็มจาก `GET` แล้วแก้ `brief`/`nodes` ตามต้องการ ระบบสร้าง `edges`, `mindmap` และ `aiStack` จากข้อมูลที่บันทึกอีกครั้ง ไม่รับ `taskId` ที่ client ปลอมขึ้น ลิงก์งานที่สร้างไว้ก่อนหน้าจะถูกเก็บตามรหัสขั้นตอน

เมื่อ `PUT` ตอบ `409` ให้เรียก `GET` ใหม่ ทบทวนความแตกต่าง และส่ง `revision` ล่าสุด ไม่ควร retry โดยเขียนทับการแก้ไขของผู้อื่นโดยอัตโนมัติ

## ผู้ดูแลระบบ

- ตอนเริ่มระบบ `ensureSchema()` สร้าง `erp_project_flows` และ `erp_docs` แบบ additive หากยังไม่มี ต้องให้บัญชีฐานข้อมูลมีสิทธิ์สร้างตาราง
- หน้าเดิมยังเปิดได้หากอ่านตารางใหม่ไม่สำเร็จ แต่หน้าฟีเจอร์จะแจ้งเตือนและป้องกันการบันทึกทับ ควรตรวจ log และสิทธิ์ฐานข้อมูลก่อนลองใหม่
- ไม่มี npm runtime dependency ใหม่ และยังใช้การเริ่มต้นแบบ Phusion Passenger เดิม
- ทดสอบด้วย `npm test` ก่อน deploy; ชุดทดสอบฐานข้อมูลจริงจะข้ามโดยปริยาย หากมี MySQL/MariaDB **ทดสอบในเครื่อง** และผู้ใช้มีสิทธิ์สร้าง/ลบฐานข้อมูลและ trigger สามารถรัน:

  ```bash
  MNG_TEST_DB_ALLOW_CREATE=1 MNG_TEST_DB_SOCKET=/path/to/test-mysql.sock \
    MNG_TEST_DB_USER=test_user npx vitest run tests/project-flow-sql.integration.test.ts
  ```

  หากจำเป็น ให้ส่งรหัสผ่านผ่านตัวแปรแวดล้อม `MNG_TEST_DB_PASSWORD` อย่างปลอดภัย ห้ามใส่ใน Git ชุดนี้สร้างฐานข้อมูลชื่อสุ่ม 2 ชุดและลบทิ้งหลังจบ ควรใช้กับ instance ทดสอบแยกเท่านั้น ไม่ใช้กับ production
