# คู่มือ 3D Office

3D Office เป็นหน้าแยกในเมนู **ออฟฟิศ** ของ Vanilla JS SPA เดิม ภาพห้องและตัวละครเป็นฉากจำลองที่สร้างด้วย Three.js ในระบบ ไม่ใช่ภาพจาก Office Land, GPS หรือกล้องจริง

## เตรียมแผนกและลงเวลา

1. ผู้มีสิทธิ์ Manager / Admin / Super Admin เปิด **ทีม** → แก้ไขสมาชิก แล้วกรอก **แผนก** (ไม่เกิน 80 ตัวอักษร) ใช้ชื่อเดียวกันสำหรับสมาชิกในแผนกเดียวกัน เว้นว่างได้ สมาชิกที่ไม่ได้กำหนดจะอยู่ในกลุ่ม **ยังไม่ระบุแผนก** ระบบไม่เดาแผนกจากตำแหน่งหรือนำค่าตัวอย่างมาใส่ข้อมูลจริง
2. สมาชิกลงเวลาในหน้า **ลงเวลา** โดยเลือกออฟฟิศหรือ WFH เมื่อมีเช็กอินของวันนั้นที่เวลาเข้าถูกต้องและไม่เป็นเวลาในอนาคต และยังไม่มีเวลาออก ตัวละครจะปรากฏในแผนกหรือจอบ้านด้านล่างตามลำดับ
3. เมื่อลงเวลาออก ตัวละครจะหายไป หากกลับมาทำงานวันเดียวกัน สามารถเลือก **ออฟฟิศ** หรือ **WFH** เพื่อเช็กอินรอบใหม่ได้ โดยเก็บเวลาเข้า–ออกของรอบก่อน ในข้อมูลจริงใช้รอบที่มี ID ล่าสุด ส่วนโหมดสาธิตใช้รายการใหม่ล่าสุดในเบราว์เซอร์ คนที่ไม่มีเช็กอินหรือข้อมูลสถานที่ไม่ครบไม่ถูกนับว่าอยู่ที่ใด กดดูรายละเอียดสถานะอื่นได้ในแผงรายชื่อ การเช็กอินเป็นข้อมูลที่ผู้ใช้บันทึก ไม่ได้ยืนยันตำแหน่งหรือการทำงานจริง
4. เลือกแผนกจากแถบข้าง (หรือเมนูบนมือถือ) ลากเพื่อหมุนภาพ ใช้ปุ่มหมุน ซูม และกลับมุมเดิม หากอุปกรณ์ไม่รองรับ WebGL หน้ารายชื่อ แผนก จอ WFH และนัดหมายยังใช้งานได้

## นัดประชุม

สร้างกิจกรรมประเภท **ประชุม** ในปฏิทิน ระบุวันที่ เวลาเริ่ม–สิ้นสุด และเลือกสมาชิกที่ได้รับเชิญ เมื่อถึงช่วงเวลาเริ่มจนก่อนเวลาสิ้นสุดในวันนั้น จะแสดงชื่อผู้ได้รับเชิญเป็นจอแยก **ไม่ใช่วิดีโอสด ไม่ตรวจไมโครโฟน/กล้อง และไม่ยืนยันว่าผู้ได้รับเชิญเข้าร่วมจริง** นัดตลอดวันหรือที่เวลาไม่ครบ/ไม่ถูกต้องอยู่ในรายการนัดอื่น ไม่ถูกแสดงว่าอยู่ในช่วงเวลาประชุม

หากต้องการปุ่มเปิดประชุม ให้วางลิงก์ **HTTPS** ของ `meet.google.com`, `zoom.us` / โดเมนย่อย หรือ `zoom.com` / โดเมนย่อย ในช่อง **สถานที่ / ลิงก์ประชุม** ของกิจกรรม ระบบเปิดลิงก์ในแท็บแยก ไม่ฝังวิดีโอ ลิงก์ที่ไม่ผ่านเงื่อนไขจะไม่เป็นปุ่ม แม้ยังเก็บข้อความสถานที่เดิมไว้ในปฏิทิน ผู้ใช้ที่เข้าสู่ระบบสามารถดูนัดหมายและลิงก์ได้ตามสิทธิ์การมองเห็นปฏิทินเดิม จึงควรใช้ข้อมูลเท่าที่จำเป็น

## ความสดและการจัดเก็บ

- เมื่อเชื่อม MariaDB หน้าดึง `/api/office/snapshot` ด้วยบัญชีที่เข้าสู่ระบบ อ่านแผนก สมาชิก เช็กอิน **ทุกรายการของวันปัจจุบัน** และกิจกรรมประชุมจากฐานข้อมูล โดยใช้วันและเวลา **Asia/Bangkok** จากเซิร์ฟเวอร์ ส่วน bootstrap สำหรับหน้าลงเวลาดึงรายการวันนี้ทั้งหมดและประวัติวันอื่นล่าสุดไม่เกิน 90 รายการ
- ระบบลงเวลาแยกตามวัน ยังไม่รองรับการลงเวลาออกข้ามเที่ยงคืนในรอบเดียวกัน กะข้ามวันจึงต้องใช้ขั้นตอนบันทึกเวลาอื่นขององค์กร
- รีเฟรชอัตโนมัติทุก 60 วินาทีขณะเปิดหน้า และกดรีเฟรชเองได้ หากคำขอไม่ตอบใน 12 วินาทีหรือโหลดไม่สำเร็จจะแจ้งเตือน หากมีข้อมูลครั้งก่อนจะแสดงพร้อมเวลาและคำเตือนว่าอาจเก่า หากยังไม่เคยโหลดสำเร็จจะไม่สร้างข้อมูลคน/นัดปลอมมาแทน
- โหมดสาธิต/ออฟไลน์ใช้ข้อมูลใน localStorage และวัน/เวลาอุปกรณ์ อาจเป็นข้อมูลตัวอย่างหรือข้อมูลเก่าที่เคยโหลดจากฐานข้อมูล จึงมีคำเตือนว่าไม่ใช่สถานะสด และการแก้ไขขณะออฟไลน์ไม่ถูกแชร์กับผู้อื่น
- `erp_team.department` เพิ่มแบบ additive อัตโนมัติเมื่อเริ่มเซิร์ฟเวอร์ ไม่แก้ไขข้อมูลแผนกของสมาชิกเดิม หากบัญชีฐานข้อมูลไม่มีสิทธิ์เพิ่มคอลัมน์ ให้ผู้ดูแลตรวจสอบ migration/สิทธิ์ฐานข้อมูลก่อน หน้าจะรายงานข้อผิดพลาดแทนการเดาข้อมูล
- ไม่แสดงบันทึกส่วนตัวของเช็กอินในหน้าออฟฟิศ แต่รายชื่อ แผนก รูปแบบเช็กอิน และนัดประชุมมองเห็นได้แก่ผู้ใช้ที่ผ่านการเข้าสู่ระบบ จัดการการเข้าถึงและข้อมูลส่วนบุคคลตามนโยบายองค์กร

## API

`GET /api/office/snapshot` ต้องผ่านการยืนยันตัวตนเช่นเดียวกับ API ERP ตอบ `date`, `time`, `timezone`, `generatedAt`, `team`, `checkins`, `events` โดย `checkins` เรียง ID ล่าสุดก่อน และ `events` มีเฉพาะหมวดประชุมในวันที่เซิร์ฟเวอร์กำหนด ไม่ได้ส่งหมายเหตุเช็กอินหรือรายละเอียดกิจกรรม หากอ่านตาราง/คอลัมน์ไม่ได้ตอบ `503 office_snapshot_unavailable`

`GET /api/teams` และ `/api/bootstrap` ส่ง `department` ในข้อมูลสมาชิก ผู้มีสิทธิ์จัดการทีมกำหนดหรือแก้ด้วย `POST /api/teams` และ `PATCH /api/teams/:id` (`{"department":"Creative"}`; ส่ง `null` หรือ `""` เพื่อล้าง) ค่าที่ไม่ใช่ข้อความหรือยาวเกิน 80 ตัวอักษรตอบ `400 invalid_department` การเปลี่ยนแผนกไม่เปลี่ยนตำแหน่งงานหรือเช็กอินเดิม
