# คู่มือ Text Speed และผู้ช่วยแมนนี่

Text Speed คือการกรอกข้อความด้วยเสียงบนหน้า ERP ส่วน **แมนนี่** คือผู้ช่วยจัดเรียง/แก้ไขข้อความในช่องที่เลือก โดยใช้ AI ที่ตั้งไว้ ฟีเจอร์นี้ไม่เปลี่ยนโครงสร้าง Vanilla JS SPA, Express/MariaDB หรือการเข้าสู่ระบบเดิม

## ข้อควรทราบก่อนใช้

- ต้องเปิดเว็บไซต์ผ่าน **HTTPS** (หรือ `localhost` สำหรับพัฒนา) ใช้เบราว์เซอร์ที่รองรับ Web Speech Recognition และอนุญาตไมโครโฟน การรองรับขึ้นกับเบราว์เซอร์/อุปกรณ์และบริการเสียง ไม่ใช่ทุกเบราว์เซอร์รองรับ ทดลองบน Chrome ที่รองรับ หากไม่มีจะแจ้งในแผง และยังพิมพ์คำสั่งแมนนี่แทนได้
- **เสียงอาจถูกส่งไปยังบริการรู้จำเสียงของเบราว์เซอร์** และต้องใช้เครือข่ายตามนโยบายของเบราว์เซอร์ ERP ไม่ได้จัดเก็บไฟล์เสียง ระบบนี้ไม่ใช่การรู้จำเสียงออฟไลน์ที่รับประกันความเป็นส่วนตัว
- เลือก **ไทย** หรือ **English** ก่อนเปิดไมค์; การสลับภาษาต้องหยุดไมค์ก่อน ไม่ใช่การตรวจจับสองภาษาอัตโนมัติ สำเนียง ชื่อเฉพาะ ตัวเลข อีเมล และคำสั่งอาจถอดผิด ควรตรวจทุกครั้ง
- เมื่อเรียกแมนนี่ **ข้อความทั้งช่องที่เลือกและคำสั่ง** จะถูกส่งไปยังผู้ให้บริการ AI ที่ใช้จริง อาจมีค่าใช้จ่ายและถูกเก็บโดยผู้ให้บริการตามนโยบายของเขา อย่าส่งข้อมูลลับ ข้อมูลส่วนบุคคล หรือข้อมูลลูกค้าที่ไม่ได้รับอนุญาต ERP ไม่บันทึกประวัติสนทนาหรือข้อความที่ส่งเป็นประวัติของแมนนี่ แต่การตั้งค่าและ key เก็บในฐานงาน
- AI อาจสะกดผิด แต่งข้อมูล ตัดรายละเอียด หรือจัดรูปแบบไม่เหมาะสม ต้องตรวจผลก่อนนำไปใช้ โดยเฉพาะข้อมูลการเงิน กฎหมายและข้อมูลลูกค้า

## วิธีกรอกด้วยเสียง

1. เข้าหน้าใดก็ได้ใน ERP แล้วเปิดปุ่ม **Text Speed** มุมขวาล่าง เลือกภาษาและกด **เปิดไมโครโฟน** อนุญาตสิทธิ์ตามที่เบราว์เซอร์ถาม สถานะ **กำลังฟัง** จะปรากฏแม้ย่อแผง
2. คลิกช่องที่ต้องการแล้วพูด ข้อความจะถูกแทรกตรงตำแหน่งเคอร์เซอร์/แทนข้อความที่เลือก สำหรับช่องที่เบราว์เซอร์ไม่รองรับตำแหน่งเคอร์เซอร์ เช่น email และ number จะต่อท้าย ในช่องค้นหาอาจกรองผลทันทีตามพฤติกรรมเดิม
3. พูดคำสั่งสั้น ๆ แยกจากข้อความที่จะพิมพ์:

| ไทย | English | ผล |
| --- | --- | --- |
| ลบตัวอักษร / ลบตัวอักษรสุดท้าย | delete character / backspace | ลบตัวก่อนเคอร์เซอร์ หรือข้อความที่เลือก |
| ลบคำสุดท้าย | delete last word | ลบคำก่อนเคอร์เซอร์ หรือข้อความที่เลือก |
| ลบทั้งหมด | delete all / clear all | ลบข้อความทั้งช่อง |
| ย้อนกลับ | undo | ย้อนการแก้ครั้งล่าสุดในช่องเดิม |
| ขึ้นบรรทัดใหม่ | new line | ขึ้นบรรทัดใหม่ใน textarea |
| หยุดฟัง | stop listening | ปิดไมโครโฟน |

คำสั่งเป็นวลีเฉพาะ หากระบบได้ยินผิดอาจพิมพ์เป็นข้อความ ให้ตรวจและกด **ย้อนกลับ** ได้ แผงเก็บการย้อนกลับสูงสุด 20 รายการในหน่วยความจำของหน้านี้ ไม่ใช่ประวัติถาวร; หากแก้ข้อความต่อหรือเปลี่ยนหน้า/รีเฟรชจนช่องเดิมหาย ระบบจะไม่ย้อนทับข้อมูลที่เปลี่ยนแล้ว

รองรับ `textarea` และ input ชนิด text/search/email/url/tel/number/date/time ที่แก้ไขได้; ช่องตัวเลขรับผลที่เป็นเลขเท่านั้น ช่องวันที่/เวลารับผลรูปแบบ `YYYY-MM-DD` / `HH:mm` ซึ่งบริการเสียงอาจถอดไม่ได้ ต้องตรวจหรือกรอกเอง ไม่รองรับ dropdown, checkbox, rich-text/contenteditable, ช่องไฟล์ หรือช่องรหัสผ่าน/OTP/API key และช่องที่ระบุว่าเป็นข้อมูลลับ การบล็อกอาศัยชนิด ชื่อ และคุณสมบัติของช่อง จึงไม่รับประกันว่าจะตรวจพบข้อมูลลับทุกกรณี ผู้ใช้ต้องไม่เลือกหรือพูดข้อมูลลับเอง ทั้งนี้ใช้งานในหน้ากับ modal ของ SPA นี้ ไม่ควบคุมหน้าเว็บหรือ iframe ภายนอก

กดหยุดเมื่อเสร็จ ไมค์หยุดเมื่อออกจากแท็บที่กำลังฟัง ออกจากระบบ หรือ session หมดอายุ การเปลี่ยนหน้า **ภายใน SPA** ไม่หยุดไมค์ จึงควรสังเกตสถานะเสมอ เบราว์เซอร์อาจหยุดบริการเองหรือปฏิเสธสิทธิ์ได้

## เรียกแมนนี่ให้ช่วย

1. เปิดไมค์ภาษาไทยแล้วพูด **“แมนนี่มานี่”** หรือกดปุ่ม **เรียกแมนนี่** ในแผง (ภาษาอังกฤษพูด `Manny come here` ได้ หากบริการรู้จำวลีนั้นถูกต้อง)
2. แมนนี่ถาม **“ให้ช่วยตรงไหน?”** ด้วยข้อความและเสียงเมื่ออุปกรณ์รองรับ ให้คลิกช่องข้อความที่ต้องการ แม้เป็นช่องเดิมที่โฟกัสอยู่ก็ต้องคลิกเลือกอีกครั้ง ช่องลับเลือกไม่ได้ ระบบพักการรู้จำขณะแมนนี่ถามและระหว่างรอ AI เพื่อไม่รับเสียงตอบของตัวเองหรือคำพูดระหว่างรอ แล้วเปิดฟังต่อเองหากยังไม่ได้กดหยุด
3. เมื่อขึ้น **เลือกช่องแล้ว** รอสักครู่ให้ไมค์กลับมาพร้อม แล้วพูดคำสั่ง เช่น “จัดเรียงให้อ่านง่ายและแก้คำผิด” แล้วเว้นช่วงเล็กน้อย หรือพิมพ์คำสั่งในแผงและกด **ให้แมนนี่ช่วย** โดยไม่ต้องเปิดไมค์
4. เมื่อ AI สำเร็จ ระบบใส่ผลกลับลงช่องโดยอัตโนมัติ **ไม่ได้กดปุ่มบันทึก ส่งแชต หรือส่งฟอร์มแทน** ควรตรวจแล้วจึงบันทึกเอง กด **ย้อนกลับ** เพื่อคืนข้อความก่อนแก้ได้ถ้าช่องยังไม่เปลี่ยน
5. หากเปลี่ยนข้อความ ปิด modal หรือเปลี่ยนหน้าในระหว่างรอ ระบบจะไม่เขียนทับโดยอัตโนมัติ ให้เรียกใหม่ ผลที่ยาวเกินช่อง ผลไม่สมบูรณ์ที่ provider ระบุว่าถูกตัด หรือผลผิดรูปแบบจะไม่ถูกใส่ หากหยุด/ยกเลิกขณะรอ เบราว์เซอร์จะละทิ้งผล แต่คำขอที่ออกจากเซิร์ฟเวอร์แล้วอาจยังถูกคิดเงิน

ระบบส่ง event `input` เช่นเดียวกับการกรอกข้อความ เพื่อให้การค้นหาและฟอร์มอัปเดตตามปกติ หากหน้าใดมีพฤติกรรมตอบสนองต่อการพิมพ์ทันที พฤติกรรมนั้นยังเกิดขึ้นได้

## ตั้งค่า AI ใน Setting

ที่ **ตั้งค่า → Text Speed & แมนนี่** ผู้ใช้แต่ละบัญชีตั้ง API key ส่วนตัวได้หนึ่งชุด พร้อมเลือก provider และ model การตั้งค่าแยกตาม `auth_user_id`; ไม่มีการใช้ประวัติสนทนาร่วมกัน บันทึก/ลบต้องยืนยันรหัสผ่าน ERP ปัจจุบัน Key ที่บันทึกแล้วจะไม่แสดงคืนในหน้าเว็บ หากต้องการเปลี่ยน ให้กรอก key ใหม่

ถ้าไม่ได้ตั้ง key ส่วนตัว ระบบจะสุ่มอย่างเท่าเทียมจาก key ส่วนกลางที่ Admin เปิดไว้ **ทุกคำขอ** (อาจได้ provider/model ต่างกัน) รายชื่อ provider/model ที่อาจถูกสุ่มแสดงใน Setting Key จริงไม่ถูกส่งให้ผู้ใช้ แต่ค่าใช้จ่ายและบันทึกฝั่ง provider อาจอยู่ในบัญชีองค์กรร่วมกัน ผู้ใช้ทุกสิทธิ์ที่เข้าสู่ระบบเว็บสามารถใช้ชุดส่วนกลางได้ Admin จึงต้องกำหนดงบ นโยบายข้อมูล และสิทธิ์ใช้งานของบัญชีให้เหมาะสม

- เมื่อมี key ส่วนตัว ระบบจะใช้ของเจ้าของเท่านั้น **ไม่เปลี่ยนไปใช้ส่วนกลางอัตโนมัติ** เมื่อ key ส่วนตัวผิด หมดโควตา หรือ provider ล่ม หากต้องการกลับไปใช้ส่วนกลาง ให้ลบ key ส่วนตัวโดยยืนยันรหัสผ่าน
- Admin/Super Admin เพิ่มหลายรายการ พัก เปิด หรือลบรายการส่วนกลางได้ที่ Setting โดยยืนยันรหัสผ่านทุกครั้ง การพักหรือลบไม่ยกเลิกคำขอที่เริ่มไปแล้ว ต้องตั้งคีย์จากผู้ให้บริการจริงเอง ไม่มีการสร้าง key หรือเปิดบริการจาก ERP
- รองรับ **OpenAI Chat Completions**, **Google Gemini GenerateContent**, **Anthropic Claude Messages** และ **OpenAI-compatible Chat Completions** เลือกชื่อโมเดลให้ตรงบัญชี/endpoint ของตน สถานะ “ตั้งค่าแล้ว” หมายถึงข้อมูลถูกบันทึก ไม่ได้ตรวจว่าคีย์ โมเดล โควตา นโยบายข้อมูล หรือบริการใช้งานได้จริง
- ไม่มี fallback หรือ retry อัตโนมัติเมื่อ provider ผิดพลาด หมดเวลา หรือส่งผลไม่สมบูรณ์ คำขออาจถูกคิดเงินแม้ไม่ได้รับผล ควรตรวจบิลก่อนลองใหม่ จำกัด 1 คำขอพร้อมกันและ 20 คำขอ/นาทีต่อผู้ใช้ **ต่อ process** เป็นเพียงขอบเขตพื้นฐาน ไม่ใช่ quota แบบกระจายหลายเซิร์ฟเวอร์หรือการควบคุมงบ

### URL สำหรับ OpenAI-compatible

ให้ใส่ URL เต็มของ Chat Completions เช่น `https://api.groq.com/openai/v1/chat/completions` ต้องเป็น HTTPS พอร์ต 443 ไม่มี username/password, query หรือ fragment โฮสต์ที่รองรับเริ่มต้น: `api.openai.com`, `api.deepseek.com`, `api.groq.com`, `openrouter.ai`, `api.mistral.ai`, `api.together.xyz` เท่านั้น Admin ฝั่งเซิร์ฟเวอร์เพิ่มชื่อโฮสต์แบบตรงตัวได้ใน `MANNY_COMPATIBLE_HOSTS` (ไม่รองรับ wildcard) ต้องเป็นบริการที่องค์กรเชื่อถือ เพราะข้อความและ key จะถูกส่งไปที่นั่น

เซิร์ฟเวอร์ไม่ติดตาม redirect ตรวจ DNS ว่าเป็น public address และ pin ผล lookup สำหรับการเชื่อมต่อ จึงไม่รองรับ endpoint ภายใน/private network; ต้องอนุญาตการออก HTTPS ไปยังผู้ให้บริการใน firewall ด้วย

## ติดตั้ง/ดูแลฝั่งเซิร์ฟเวอร์

1. สำรองฐานงาน ตรวจสิทธิ์สร้างตาราง `erp_manny_user_settings` และ `erp_manny_shared_keys` แบบ additive; `/api/db/audit` ตรวจนับ 29 ตารางรวมฐาน auth แต่ไม่ได้ตรวจ schema ทุกคอลัมน์
2. สร้าง master key แบบสุ่ม **64 ตัวอักษร hex** เช่น `openssl rand -hex 32` แล้วตั้ง `MANNY_ENCRYPTION_KEY` ผ่าน secret manager หรือ environment ของ Passenger/Node บนเซิร์ฟเวอร์จริง อย่าใส่ key จริงลง Git แชต หรือ `.env.example` อาจตั้ง `MANNY_COMPATIBLE_HOSTS` เป็นรายชื่อโฮสต์ที่เชื่อถือ คั่นด้วยจุลภาค ดู `server/.env.example`
3. รีสตาร์ตบริการตามขั้นตอนโฮสต์ เข้า Setting ด้วย Admin เพิ่ม key ส่วนกลางจากผู้ให้บริการจริง แล้วทดสอบด้วยข้อมูลตัวอย่างและตรวจค่าใช้จ่าย/นโยบายของ provider การไม่มี master key **ไม่ปิดการกรอกเสียง** แต่บันทึกหรือถอดรหัส key AI ไม่ได้
4. สำรอง master key แยกจากฐานข้อมูลและจำกัดผู้เข้าถึง Key ของผู้ให้บริการเก็บเป็น AES-256-GCM พร้อมผูกกับเจ้าของ/รหัสรายการ ไม่ใช้ DB password หรือคีย์เริ่มต้น หากเปลี่ยนหรือทำ master key หาย จะอ่าน key ที่เข้ารหัสเดิมไม่ได้ ต้องกู้ master key เดิมหรือลบ/ตั้ง API key ใหม่ทุกชุด อย่าหมุนค่านี้โดยไม่มีแผน
5. ฐานข้อมูลและ environment/secret manager ยังเข้าถึงได้โดยผู้ดูแลเซิร์ฟเวอร์ที่มีสิทธิ์; การเข้ารหัสไม่ได้ป้องกันผู้ที่ควบคุมแอปหรือ provider ควรจำกัดการเข้าถึง สำรอง และตั้งนโยบายเก็บข้อมูลตามองค์กร

โหมดสาธิต localStorage ไม่เรียก AI จริง; ขณะนี้ยังต้องทดสอบการรู้จำเสียงและ provider จริงด้วยอุปกรณ์ บัญชี เครือข่าย และ key ขององค์กรก่อนใช้งานจริง

## API และการทดสอบ

Endpoint ทั้งหมดอยู่ใต้ `/api/manny` ต้องเป็น **web session ของบัญชีที่ยัง active** ไม่รับ Hermes token และคำขอจากเบราว์เซอร์ต้องมาจาก origin เดียวกัน Key และรหัสผ่านส่งผ่าน HTTPS เท่านั้น:

| Method | Path | หน้าที่ |
| --- | --- | --- |
| GET | `/settings` | สถานะส่วนตัวและรายการ provider ที่สุ่มได้; เฉพาะ Admin เห็น metadata ของชุดส่วนกลาง ไม่มี key จริง |
| PUT / DELETE | `/personal` | ตั้ง/ลบ key ของบัญชีปัจจุบัน ต้องมี `password` ของเจ้าของ |
| POST | `/shared` | Admin เพิ่ม `{label, provider, model, endpoint?, apiKey, password}` |
| PATCH / DELETE | `/shared/:id` | Admin เปิด/พักด้วย `{enabled, password}` หรือลบด้วย `{password}` |
| POST | `/assist` | `{text, instruction, confirm:true}` ส่งข้อความไป provider คืน `{text, provider, model, source}` ไม่สั่งบันทึกฟอร์ม |

`npm test` ทดสอบตัวเข้ารหัส, provider adapters จำลอง และ UI จำลอง Speech Recognition หากต้องการ MariaDB จริง ให้รันบน **Unix socket ของฐานข้อมูลทดสอบในเครื่องเท่านั้น** ด้วย `MNG_TEST_DB_ALLOW_CREATE=1 MNG_TEST_DB_SOCKET=/path/to/test.sock npm test`; ชุด SQL สร้างและลบฐานข้อมูลชื่อสุ่ม ห้ามชี้ไป production การทดสอบ provider จำลองและเบราว์เซอร์จำลองเสียงไม่แทนการลองไมโครโฟนและบัญชี AI จริง
